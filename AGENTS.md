# AGENTS.md

Guidance for AI coding agents working on this repository.

## Project overview
- Personal website of Michael Troger, served at https://michaeltroger.com through **GitHub Pages**.
- Static site built with **Jekyll** (`github-pages` gem), **Kramdown** Markdown, **Liquid** templates, **SCSS** and plain **JavaScript**.
- All site sources live in `docs/`. GitHub Pages builds from that folder on every push to `master`.
- No license is granted (see `README.md`). Don't add license files or third-party code without explicit permission.

## Repository layout
- `docs/` – Jekyll site root
  - `_config.yml` – site config (title, url, permalink, source URLs)
  - `_layouts/` – `default.html` (main layout), `lang-redirect.html` (detects language, then redirects), `redirect.html` (static redirect)
  - `_data/` – `languages.yml` (supported languages), `i18n.yml` (UI strings per language), `apps.yml` (app names, some localized)
  - `_sass/`, `css/main.scss` – styles
  - `js/` – `lang.js` (language redirect + picker), `contact.js` (contact form, OpenPGP encryption), `openpgp.min.js(.map)` (generated, see below)
  - `<lang>/<section>/index.md` – localized content pages
  - `<section>/index.md|html` – language-neutral entry points (`lang-redirect` layout)
  - `<section>/<lang>/index.html` – legacy redirect stubs (`redirect` layout)
  - `sitemap.xml`, `robots.txt`, `404.md`, `CNAME`, `files/`, `images/`
- `openpgpjs/` – git submodule of OpenPGP.js. It's only used to build `docs/js/openpgp.min.js`.
- `screenshots/` – generated by CI, don't edit by hand.
- `testreport.txt` – Mozilla Observatory report generated by CI, don't edit by hand.
- `.github/workflows/` – `deploy.yml` (daily Pages rebuild), `screenshots.yml`, `security_test.yml`, `update_openpgpjs.yml`.
- `.devcontainer/` – dev container that runs `bundle install` and `jekyll serve` in `docs/`.

## Build & run locally
```bash
cd docs
bundle install
bundle exec jekyll serve        # http://localhost:4000
```
- There's no automated test suite. Check changes by running `bundle exec jekyll build` in `docs/` (it must succeed without errors) and looking at the affected pages locally.
- Never commit build output (`docs/_site/`, `.jekyll-cache/`, `.sass-cache/`, `.jekyll-metadata`).

## Internationalization (important)
Supported languages are defined in `docs/_data/languages.yml`: `en`, `de`, `es`, `fr`, `it`, `pt`.
- Every content page exists once per language at `docs/<lang>/<section>/index.md`. When you change content, update **all** language versions consistently. English (`en`) is the reference.
- UI strings (navigation, footer) go in `docs/_data/i18n.yml`. Add every new key for every language.
- Localized app names go in `docs/_data/apps.yml` and are used as `{{ site.data.apps.<key> }}`.
- Internal links must include the language prefix, e.g. `/de/apps/`. Don't link to language-neutral paths from localized pages.
- Adding a new section:
  1. Create `docs/<lang>/<section>/index.md` for every language with front matter `layout: default`, `title`, and `description` (or `noindex: true`).
  2. Add a language-neutral entry `docs/<section>/index.md` using `layout: lang-redirect`, `section: <section>` and `permalink: /<section>/`.
- Adding a new language: update `_data/languages.yml`, `_data/i18n.yml`, the `supported` array in `docs/js/lang.js`, and create every `docs/<lang>/...` page.
- `hreflang` and canonical links, as well as `sitemap.xml`, are generated automatically from `languages.yml`. Pages with `noindex: true` or `sitemap: false` are left out of the sitemap.

## Security & privacy constraints
- Every layout sets a strict Content Security Policy (`default-src 'none'; script-src 'self'; style-src 'self'; ...`). This means:
  - No inline `<script>`, inline event handlers (`onclick=`), inline `style=` attributes or `<style>` blocks. Put code in `docs/js/` and styles in SCSS.
  - No external scripts, fonts, styles, images, analytics or trackers. Everything must be self-hosted.
- Keep `<meta name="referrer" content="no-referrer">` and the robots/noai meta handling in the layouts.
- Don't add cookies, tracking or personal data collection. Doing so would contradict the privacy policy pages.
- Keep email addresses obfuscated (HTML entities), as in the existing pages.
- `robots.txt` blocks AI crawlers from the privacy, imprint, contact and signal pages. Keep it that way when adding similar sections.
- Never commit secrets or tokens. CI uses repository secrets (e.g. `USER_TOKEN`).

## Generated / CI-managed files
- `docs/js/openpgp.min.js` and `.map` are built from the `openpgpjs` submodule by `update_openpgpjs.yml`. Don't edit them manually or change the submodule without being asked.
- `screenshots/*` and `testreport.txt` are updated by CI through pull requests.

## Code style
- Follow the style of the surrounding files: tabs in the HTML layouts, 2-space indentation in `lang.js`, and plain ES5-compatible JavaScript without frameworks or build steps.
- Use Liquid helpers (`relative_url`, `absolute_url`, `{% link %}`) for internal URLs in templates.
- Content is written in Markdown (Kramdown). Keep front matter minimal and consistent with the other pages.
- Don't add new gems, npm packages or build tooling unless explicitly requested. The site must keep building on plain GitHub Pages.

## Commits
- Only commit when explicitly asked. Keep commit messages short and imperative (e.g. "Improve language picker").
